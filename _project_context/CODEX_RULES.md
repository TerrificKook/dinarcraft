# CODEX RULES

## Главные правила работы с сайтом

- Отвечать пользователю на русском языке.
- Объяснять простыми словами, без лишнего жаргона.
- Помнить, что владелец проекта не программист.
- Перед правками кратко объяснять, что будет изменено.
- Делать изменения маленькими шагами.
- После правок перечислять измененные файлы и объяснять, зачем они изменены.
- Всегда давать команды для запуска и проверки проекта, если они нужны.

## Что нельзя делать без прямой команды

- Не делать commit.
- Не делать push.
- Не удалять файлы без подтверждения.
- Не менять `sitemap.xml` без отдельного разрешения.
- Не менять `robots.txt` без отдельного разрешения.
- Не подключать WordPress, CMS, React, Node, Vite, сложные сборщики и тяжелые библиотеки без отдельной необходимости.
- Не переписывать большие части проекта без явной причины.
- Не публиковать фейковые цены, отзывы, рейтинги, адреса и несуществующие факты.

## Правила для файлов и контента

- Не загружать рабочие папки `_site_import`, исходные фото, Excel, CSV и другие рабочие файлы.
- Не копировать изображения, видео, Excel, CSV и рабочие файлы в контекстный пакет.
- Все имена файлов желательно делать латиницей.
- Все пользовательские тексты на сайте должны быть на русском.
- Контакты не менять без явной команды:
  - телефон: `+7 (995) 881-50-95`;
  - телефонная ссылка: `tel:+79958815095`;
  - email: `db@dinardb.ru`;
  - Telegram: `https://t.me/mrdinar`.
- MAX добавлять только после получения точной ссылки или профиля.

## Правила для структуры сайта

- Не ломать структуру каталога.
- Не менять URL товарных страниц без отдельной SEO-причины.
- Не удалять старые SEO-страницы без проверки.
- Не удалять файлы подтверждения Яндекс Вебмастера.
- Не менять canonical-ссылки без проверки.
- Не менять папки изображений товаров без необходимости.

## Как работать после правок

После любых изменений нужно сообщать:

- какие файлы изменены;
- зачем они изменены;
- как проверить результат;
- какие риски остались, если они есть.

Если появилась ошибка, нужно объяснить ее человеческим языком и предложить следующий шаг.
