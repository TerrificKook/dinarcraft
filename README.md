# DINAR handmade site

Статический B2B-сайт мастерской DINAR handmade для GitHub Pages и домена `dinarcraft.ru`.

DINAR handmade производит изделия из кожи и стропы оптом, брендированные партии и изделия под задачу заказчика. Сайт показывает каталог, производственные услуги, условия сотрудничества и принимает запросы на расчёт.

## Архитектура

Сайт работает без CMS, фреймворка и сборщика. Публичные страницы состоят из обычных HTML-файлов, общих CSS-стилей и небольшого JavaScript.

Основные разделы:

- `/` — главная страница;
- `/catalog/` — каталог, товарные и групповые страницы;
- `/services/` — производственные услуги;
- `/cooperation/` — условия сотрудничества;
- `/articles/` — опубликованные статьи;
- `/privacy/` — политика обработки данных;
- `/assets/` — общие стили, скрипты и изображения;
- `/docs/` — внутренняя документация по контенту и статьям.

Основные общие файлы:

- `assets/site.css` — оформление всех типов страниц;
- `assets/site.js` — мобильное меню, аналитика, цели и уведомление о cookies;
- `assets/product-gallery.js` — галереи изображений на товарных страницах;
- `assets/images/products/` — изображения товаров по отдельным папкам;
- `sitemap.xml` — список публичных URL для поисковых систем;
- `robots.txt` — правила обхода сайта поисковыми роботами;
- `CNAME` — привязка GitHub Pages к домену `dinarcraft.ru`.

Файл `privacy.html` сохраняется как переход со старого адреса на актуальную страницу `/privacy/`. Файлы `yandex_*.html` и `google*.html` используются для подтверждения прав в сервисах поисковых систем.

## Коммерческие условия на сайте

Актуальная формулировка для отгрузок:

- отгрузки от 30 000 ₽;
- сумма без учета логистики;
- логистика рассчитывается отдельно;
- стоимость и состав партии подтверждаются после согласования ТЗ.

Эту логику нужно держать одинаковой в SEO-описании, блоке каталога, условиях сотрудничества и тексте доставки/оплаты.

## Работа с изображениями

Изображения товаров хранятся в `assets/images/products/<product-folder>/`. У товарной страницы и соответствующей папки изображений должен быть одинаковый идентификатор товара. Перед заменой или удалением изображения нужно проверить все ссылки на его путь в HTML.

## Рабочий процесс

Обычная последовательность работы:

1. Правки через Codex Desktop.
2. Локальная проверка страниц и ссылок.
3. Просмотр изменённых файлов в GitHub Desktop.
4. Отдельно подтверждённые commit и push.
5. Публикация через GitHub Pages.

Commit и push не следует выполнять вместе с непроверенными или посторонними изменениями.

## Важные проверки перед публикацией

- `CNAME`, canonical-ссылки, `robots.txt` и `sitemap.xml` должны указывать на `dinarcraft.ru`.
- Новая публичная страница должна существовать до добавления ссылки на неё и URL в sitemap.
- Нельзя удалять `privacy.html` и файлы подтверждения поисковых сервисов без отдельной проверки.
- После правок нужно проверить `git status --short`, локальные ссылки и отображение страницы на компьютере и телефоне.
